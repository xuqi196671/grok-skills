# 现成优先

动手新建（技能、助手、例行、流程、方案、代码）之前，先找应用里和网上已经差不多的东西。能复用就不从零造。

改编思路来自公开的 creation-guard / search-first 类实践，并与「搜索优先」「动手前先调研」互补：本技能覆盖技能与助手等工件，不限于写代码。

## 原则

1. **先查后写** — 未检索就开写，算跳步。
2. **应用内优先，网上紧随** — 先扫本应用已有能力，再搜公开网页/GitHub/技能库；两边都看过再决定。
3. **能改就别新建** — 高度重合时扩展或组合已有项，而不是再堆一个近似副本。
4. **点明依据** — 采用/扩展/组合/自建时，用一两句说明找过什么、为何这样裁。

## 查找顺序

1. **应用内**
   - 已有用户技能与插件技能（名称、description、正文关键词）
   - 已有助手职责是否已覆盖
   - 已有例行、连接器、频道是否可直接用或稍改
2. **网上**
   - 公开技能模板、GitHub、文档、包/库（按任务类型选）
   - 记下 1–3 个最接近的候选与链接/路径
3. **本地缓存**（若任务会反复用数据）— 先读本地已有材料，再决定是否外拉

## 裁决（四选一）

写完检索后必须落一句：

`裁决：采用 | 扩展 | 组合 | 自建 — <名称> — <理由>`

- **采用** — 现成几乎够用，直接用或安装/唤起
- **扩展** — 改已有技能/助手说明/例行，补缺口
- **组合** — 多个现成件串起来即可
- **自建** — 检索后仍无合用项，再新建；新建时可借鉴网上结构，不抄专用细节

## 何时必须走本流程

- 新建或大改技能、助手、例行、通用流程
- 用户说「写一个…」「加一个…」而你正要造新工件
- 感觉「好像做过类似的」或名字不同但目的可能重复

可跳过：用户已指定就用某一现成件；纯一字级润色；与已有能力明显无关的琐碎一步。

## 与其它技能的边界

- **搜索优先** — 侧重写代码前找库/仓库
- **动手前先调研** — 侧重选型裁决话术
- **现成优先** — 侧重技能/助手/例行等工件防重复，并明确「应用内 → 网上」顺序

可叠用：先本技能定「有没有现成工件」，写代码时再走「搜索优先」。

## 注意

- 搜的是用途与触发场景，不只是名字像不像
- 网上模板只作结构参考；落盘时仍要通用、中文（见「能中则中」），去掉他人环境专属细节
- 删除现成件属不可逆，走「可逆直做」先问；新建/扩展一般可直接做并告知
