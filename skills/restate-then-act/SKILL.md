# 先复述再动手

动手做非琐碎任务之前，先用自己的话把用户意图复述一遍，确认理解没错再推进。这一轮先停手；用户点头后再做。做的过程中同一件事保持开着：卡住交给用户，用户回了接着做，不要提前结案。

## 何时用

- 用户交代了要做的事，你准备开始查、写、改、跑之前
- 需求有目标、范围、约束或多步骤，理解偏一点成本高

可跳过（直接做，不必复述等确认）：

- 一眼无歧义的单步小事（改个错字、查个已知路径、回答事实短问）
- 纯问答、解释
- 用户刚纠正过你的理解，且新说法已经清楚
- 用户明确说「别确认了直接做 / 按你理解干 / 按这个做 / 接着做」

## 开口先这样

1. **我理解你要的是** — 一两句，结果长什么样
2. **我会做的** — 准备交什么
3. **可能理解偏的点** — 有才写（只点最影响结果的 1–2 处）
4. **请回** — 没问题 / 改哪一点

## 步骤

1. **听完再复述** — 读完本轮完整交代（含附件要点），不要只抓半句。
2. **用自己的话写短复述** — 按上面「开口」结构，2–5 句内说清要达成什么、范围与边界、关键约束；可选一句准备怎么做的第一步。
3. **标出不确定点** — 有歧义用二选一或短问，不甩长问卷。
4. **本轮先停手** — 用户点头前：禁止写成品文件、禁止跑会改东西的命令。
5. **等用户点头再开干** — 用户说「对」「可以」「没问题」「开干」「就是这样」或补正后，再执行；若用户改了理解，以改过的为准再复述一句（极短）后动手。
6. **卡住继续** — 做不完或卡住，只问缺口，等他回完继续，不要结案。
7. **开干后少打断** — 已确认的方案执行中，不为可逆细节反复复述；只有目标或约束实质变化时再复述。

## 复述示例

用户：帮我把上周的销售表做成一张给老板看的一页纸总结，别写太长。

复述：你要一份面向老板的一页纸总结，材料是上周销售表；重点是结论和关键数字，篇幅短。我先读表再出一版简体中文摘要。这样理解对吗？

## 注意

- 复述是核对理解，不是重述用户原话；不要鹦鹉学舌整段粘贴
- 不要把复述写成完整方案审批；方案细节可在确认后边做边说
- 与「可逆直做」一起用：复述确认的是**任务理解**；具体不可逆操作（发、删、花钱）仍要单独再问
- 与「现成优先」一起用：确认理解后，动手前仍先查有无现成技能/方案
- 用户可见文案用简体中文（「能中则中」）
